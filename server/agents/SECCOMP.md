The agent container uses `seccomp.json`, derived from the [Moby default profile](https://github.com/moby/profiles/blob/main/seccomp/default.json), retrieved November 4, 2026. Its upstream SHA-256 before modification was `6416b47770785a41ac59073cdc77d9fe98517df2799dc83ef207e622de3053f6`. The upstream Apache 2.0 license is retained in `seccomp.LICENSE`.

One additional allow rule permits `clone`, `unshare`, `mount`, `umount2`, `pivot_root`, and `setns` so Bubblewrap can create nested **unprivileged** namespaces. The parent container remains non-root, with all capabilities dropped, `no-new-privileges`, a read-only root, no host socket or device mounts, and CPU/memory/PID limits. The other default syscall restrictions, including the `clone3` fallback, remain. This profile applies only to Codex and its permission probes; preparation, inspection, installation and tests retain Docker's built-in default profile.

The readiness check actually runs commands in both named Codex permission profiles, verifies workspace write permissions, checks that the credential directory is unreadable to tools, and requires tool network denial. Agent tools cannot read `/home/node/.codex` or `/proc`; only the parent CLI can authenticate. Project-local configuration is untrusted, user configuration and exec rules are ignored, and web search is disabled. A failed probe blocks execution; the service never automatically disables sandboxing or adds privileges.

The profile hash is included in each planning approval and saved as `execution-policy.json`. Changing the profile or configured image name invalidates approval of a later stage. This is a single-owner, private-project runner, not a hostile-code multi-tenant service. Keep the container runtime and host patched. No machine-wide namespace or AppArmor policy is modified.
